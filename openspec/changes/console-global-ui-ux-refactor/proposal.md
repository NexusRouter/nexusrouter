## Why

NexusRouter 网关控制台（`web/dashboard`）已具备登录/引导、仪表盘、上游、模型库、API Key、访问日志、网关策略聚合页与系统设置等完整能力，但**信息架构扁平、术语与后端概念混排、各页交互模式不统一、危险操作确认强度不一致**，导致技术用户（SRE、平台、集成方）在「配置—验证—排障」链路上频繁上下文切换，误触删除/覆盖的风险偏高。在**不改动网关 HTTP API 契约与业务语义**的前提下，需要对控制台做一次**全局 UI/UX 走查与体验重构**，把流程、术语、导航与风险控制拉到同一套产品标准上。

## What Changes

- **信息架构与导航**：将当前单层侧栏扩展为**可理解的域分组**（例如：概览与观测、流量与路由、安全与策略、账号与系统），保留现有 URL 与后端资源边界，通过分组与面包屑/页内锚点降低「找功能」成本；兼容既有路由与 hash 深链（如 `/gateway/policy#section-rate-limits`），并明确**推荐入口**与**弃用展示**策略。
- **术语与心智模型**：建立**控制台受控词表**（中英对照）：区分「网关对外凭证」「上游厂商/端点」「策略（限流/CORS/IP）」等；用户主文案避免裸露 `snake_case` 键名作主标题；与 `admin-i18n` 对齐，禁止中英文各写一套矛盾描述。
- **交互一致性**：统一列表/表单/抽屉的模式（空态、加载、错误、成功反馈）；**危险操作**（删除 API Key、上游、模型库实体、规则等）统一为**二次确认 + 后果说明 + 可选名称核对**的强度分级，避免仅 `Button danger` 无弹窗或各页 `Modal.confirm` 文案不一。
- **流程连贯性**：在关键路径上提供**下一步引导**（如：无上联时引导去上游/模型库；策略页与日志页交叉链到排障）；登录后默认落地与侧栏高亮逻辑保持可预测。
- **风险与权限透明**：延续 `admin-rbac` 与现有只读规则，在 UI 上明确**为何禁用**（Operator vs Admin），避免静默失败；批量操作与导出保持与现网 API 一致的前置校验提示。
- **非目标（明确不做的后端变更）**：不新增或修改管理端 REST 路径与请求/响应 schema；不改变鉴权、Bootstrap、告警 API 语义；不以「重做视觉品牌」为首要目标（可在设计稿中收敛 token，但以后端兼容为前提）。

## Capabilities

### New Capabilities

- `admin-console-global-ux`：约束控制台**全局壳层**（导航分组、页头/上下文、跨页一致的空/错/载态）、**危险操作分级**、**术语词表与文案规则**、**关键路径内链**及与现有单页 UX 规格（如 `gateway-policy-page-ux`、`system-settings-page-ux`、`model-library-admin-ux`）的**层级关系**；仅增加前端体验层需求，后端逻辑保持不变。

### Modified Capabilities

- `dashboard-frontend`：在「管理控制台路由与导航」等章节**增量**要求：侧栏域分组、全局一致的危险操作与空态基线、与 `admin-console-global-ux` 的引用关系（不要求删除既有页面级需求）。
- `admin-i18n`：**增量**要求：控制台核心术语的命名空间/词表约束、禁止主文案硬编码与双语漂移的抽检规则。

## Impact

- **前端**：`web/dashboard/src/layouts/AdminLayout.tsx`、各 `pages/*.tsx` 的交互与文案、`locales/zh.ts` / `en.ts`、可抽取的共享组件（确认对话框、空态、术语提示等）；与现有 TanStack Query / 路由结构兼容。
- **后端**：无契约变更预期；仅复用现有管理 API。
- **规范**：`openspec/specs/` 中新增 `admin-console-global-ux`，并对 `dashboard-frontend`、`admin-i18n` 追加 delta 需求；与已归档或进行中的单页 UX 变更并存时，以全局规格为**横切约束**、单页规格为**补充**。
