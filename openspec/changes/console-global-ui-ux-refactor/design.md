## Context

- **产品**：NexusRouter 管理控制台（`web/dashboard`，React 19 + Vite + Ant Design 6 + Tailwind v4）通过现有管理 API 操作网关；路由见 `App.tsx`，壳层见 `AdminLayout.tsx`。
- **现状**：侧栏为**扁平 8 项**；网关侧已将限流/CORS/IP 等收敛到 **`/gateway/policy`**（旧路径重定向 + hash 锚点）；各页对**删除类操作**有的用 `Modal.confirm`，有的仅用危险按钮；文案分散在 `locales/*`，与后端键名/英文缩写混排风险仍在部分页面存在。
- **约束**：本设计**不改变** `services/gateway` 的 REST 契约、状态码与 RBAC 规则；不引入新的服务端资源。与进行中的单页 UX 规格（如系统设置、网关策略、模型库）并存时，本变更提供**横切**约束，单页规格继续描述页面特有布局。
- **干系人**：自建/私有化部署的**技术用户**（管理上游、密钥、策略与排障）为主；Operator 与 Admin 的能力边界保持不变。

## Goals / Non-Goals

**Goals:**

- 建立可落地的**全局导航与信息架构**（域分组 + 保留深链与书签兼容）。
- 统一**危险操作**交互强度与文案结构，降低误删与误覆盖。
- 固化**术语与 i18n 规则**，减少中英文与「用户语言 / 开发者语言」混用。
- 统一**空态、加载、错误**的最低标准，避免各页自行一套。
- 在关键路径提供**轻量跨页引导**（链到相关页或锚点），不新增向导式流程后端。

**Non-Goals:**

- 替换 Ant Design 或重做整套视觉品牌；不以「像素级设计系统重构」为交付条件。
- 新增网关 API、WebSocket、或把配置审批流做进 MVP。
- 一次性重写所有页面组件；允许**分阶段**落地，但规格先定义全链路标准。

## Decisions

1. **导航：域分组 + 保留扁平路径**  
   - **决策**：在 `AdminLayout` 侧栏用**分组标题**（纯展示，不改变 `path`）将现有项归入 3～4 个域（建议：**概览与观测** — 仪表盘、访问日志；**流量与接入** — 上游、模型库、API Key；**安全与策略** — 网关策略；**系统** — 设置）。  
   - **理由**：解决「平铺找不到」且不破坏书签与文档中的 URL。  
   - **备选**：新增顶层路由前缀（如 `/traffic/upstreams`）— **拒绝**，因破坏现有链接与文档，后端也无对应资源边界。

2. **深链：继续以 hash 为主，补充「页内目录」**  
   - **决策**：保留 `/gateway/policy#section-*`；在策略页内提供**固定或吸顶锚点导航**（与现有 `gateway-policy-page-ux` 对齐），全局规格只要求「从侧栏进入策略页时可见入口与当前段」之一致体验。  
   - **理由**：零后端成本；hash 由前端滚动处理。  
   - **备选**：改为子路由 `/gateway/policy/rate-limits` — **搁置**，需路由与重定向矩阵扩大，可作为二期。

3. **危险操作：三级强度**  
   - **L1**（可逆/低影响）：单条 `Modal.confirm` + 说明后果。  
   - **L2**（删除凭证/上游/规则等）：确认 + **明确资源名称**展示 + 主操作二次强调（与 Ant Design `okType="danger"` 一致）。  
   - **L3**（批量/不可逆，若未来出现）：名称输入或勾选「我已知晓」。  
   - **决策**：先统一 **L1/L2** 的组件封装（如 `confirmDestructive({ title, resourceLabel, onOk })`），各页传入 i18n 键。  
   - **理由**：与当前代码中混用按钮与 Modal 的现状对齐，改造成本可控。

4. **术语：集中词表 + 命名空间**  
   - **决策**：在 `locales` 增加 `glossary.*` 或 `consoleTerms.*` 前缀，侧栏与页面标题优先引用词表；后端键名、HTTP 头名仅出现在 Tooltip / 高级说明。  
   - **理由**：满足「技术用户」既要准确又要可读；与 `admin-i18n` 增量规格一致。  
   - **备选**：每页自建文案 — **拒绝**，会再次导致不一致。

5. **与 RBAC 的 UI 表达**  
   - **决策**：延续禁用保存与隐藏入口的现有行为；**增量**要求对禁用控件提供**统一短说明**（Tooltip 或页内 Alert），引用角色名（Admin / Operator）由 i18n 提供。  
   - **理由**：减少「点了没反应」的隐式失败感；不改变权限判定逻辑。

6. **实现拆分顺序**  
   - **决策**：先壳层（导航分组、全局确认组件、空态占位组件）→ 再按流量最高的页面（API Key、上游、策略、模型库）替换危险操作与空态 → 最后扫尾仪表盘与日志。  
   - **理由**：优先降低误操作与「找不到入口」两类痛点。

## Risks / Trade-offs

- **[Risk] 分组命名主观** → 通过规格中的**域—菜单映射表**固定，并在中英文下各审一轮。  
- **[Risk] 统一 Modal 与现有业务异步删除竞态** → 封装层统一 `onOk` 返回 Promise，`confirmLoading` 由 Ant Design Modal 处理。  
- **[Risk] 与单页 UX 变更冲突** → 以 `admin-console-global-ux` 为横切；单页规格仅补充该页特有布局，重复处以全局规格为准。  
- **[Trade-off] 不做路由重构** → 短期 URL 仍偏技术化，靠分组与面包屑缓解。

## Migration Plan

- **部署**：纯前端发布；无数据迁移。  
- **回滚**：恢复上一前端构建；无网关回滚依赖。  
- **分阶段发布**：可在功能开关（环境变量或简单常量）下逐步启用「新侧栏分组」与「统一确认框」，默认建议**一次合并**以减少双轨维护（若团队希望灰度，可在 tasks 中拆 PR）。

- 是否在仪表盘增加「健康检查清单」组件 — **可选**，未纳入 MVP 规格，若加则仅消费现有 API。
