## Why

在核心管理台落地后，运维仍需在故障排查、容量与合规场景下**检索历史请求轨迹**、**细粒度调整限流与跨域**、以及**按 IP 控制访问面**。当前限流与 CORS 主要依赖 `gateway.yaml` 静态段落与文件编辑，代理访问日志虽可落盘但缺少统一查询与导出；IP 控制分散或缺失。本变更将进阶能力产品化，降低排障与策略迭代成本。

## What Changes

- **日志查询**：按**时间范围**、**请求路径**、**HTTP 状态**、**API Key（指纹/脱敏维度）**、**客户端 IP** 等条件检索请求/响应日志（字段范围以实现为准）；支持结果 **CSV 导出**。
- **限流规则配置**：在管理面板中**可视化**维护限流规则（至少覆盖**按 API Key**、**按 IP** 维度），支持**阈值**、**生效范围**（路径前缀或全局等，在设计中固定枚举）；**新增、编辑、删除**规则并**实时生效**。
- **跨域（CORS）配置**：可视化配置**允许域名**、**方法**、**请求头**；支持**批量添加域名**；变更与运行时一致并**实时生效**（与现有 `gateway.yaml` CORS 段对齐或扩展）。
- **黑白名单管理**：可视化维护 **IP 白名单** 与 **IP 黑名单**（类型可区分）；支持**批量添加/删除**；与请求处理链衔接并**实时生效**。

## Capabilities

### New Capabilities

- `admin-access-log-query`: 管理端请求/响应（或访问）日志的筛选查询与 CSV 导出契约。
- `admin-rate-limit-policy`: 可多条、可编辑的限流规则模型及与网关处理顺序的契约（相对单一 `rps_per_ip` / `rps_per_key` 的扩展）。
- `admin-cors-management`: 管理端对 CORS 允许域名/方法/头的维护与批量域名、实时生效要求。
- `admin-ip-access-control`: IP 黑/白名单的数据模型、批量操作、优先级或互斥语义及实时生效。

### Modified Capabilities

- `gateway-backend`: 新增或扩展管理 API、日志索引/查询后端、规则与名单的持久化与热更新路径；请求链中插入名单与（若适用）规则匹配顺序的规范增量。
- `dashboard-frontend`: 新增日志查询、限流规则、CORS、IP 名单等页面与导航；与现有技术栈一致。

## Impact

- **后端**：`services/gateway` 的日志管线（现有 `proxy_access_log` 或新增存储）、配置合并与校验、`runtime`/中间件扩展；可能引入轻量索引（内存/文件/可选外部存储在设计中选定）。
- **前端**：`web/dashboard` 多页表格、筛选表单、导出与批量编辑交互。
- **运维与安全**：日志与导出可能含敏感元数据，需权限、脱敏与保留策略；名单误配可导致锁站，需明确默认行为与回滚。
