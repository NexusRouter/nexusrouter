## Context

管理端模型库当前实现为单页四标签（`vendors` / `bases` / `upstreams` / `instances`），见 `web/dashboard/src/pages/ModelLibrary.tsx`：各实体独立表格与独立「新建」入口，实例表单通过下拉选择 `base_model_id`、`vendor_id`、`upstream_id`。该结构忠实映射四张表，但与用户目标「让某逻辑模型在某厂商某上游上可调用」不一致，缺依赖时用户需在标签间手动补齐。后端已稳定暴露 `/api/admin/v1/model-library/*` CRUD，四表聚合与公开 `GET /v1/models` 行为以 `openspec/specs/model-library/spec.md` 为准，本变更不触碰。

## Goals / Non-Goals

**Goals:**

- 以**可路由实例（`model_instance`）列表**作为默认主视图，展示逻辑模型名、`model_code`、厂商、上游摘要、启用态等关键列，支持跳转编辑与「新建可用模型」主 CTA。
- 提供**向导模式**：按固定顺序（厂商可用性 → 上游端点 → 逻辑模型目录项 → 实例绑定）单线完成，每步可内嵌创建缺失依赖并回写。
- 提供**专家模式**：保留按实体维度的列表与编辑（可收纳为二级入口或「高级」区域），满足批量维护与排障。
- **术语与释义**：界面主标签使用业务向中文（及 en 资源），原技术词以副标题、Tooltip、`?` 短释义呈现；与 `admin-i18n` 键值扩展一致。
- **下拉内嵌新建**：在实例、上游等表单中，`Select` 支持「+ 新建 …」打开子表单（Modal/Drawer），成功后刷新选项并选中新建项。

**Non-Goals:**

- 不修改数据库 schema、不新增/变更管理端 REST 路径与请求体字段语义。
- 不改变网关路由、鉴权、操作员只读策略的后端行为。
- 不要求一次发布即删除旧四标签实现；可采用同路由下渐进替换或短期特性开关（若团队需要安全回滚）。

## 术语对照表（界面 ↔ 技术）

| 用户向主文案（中文示例） | 技术实体 / 字段 | 极简释义（Tooltip 可用） |
|--------------------------|-----------------|---------------------------|
| 厂商 / 服务品牌 | `model_vendor` | 模型提供方或聚合渠道，用于展示归属与分组 |
| 接入端点 / API 接入 | `model_upstream` | 一条可访问的 HTTP 上游配置（`base_url`、密钥、超时等） |
| 模型目录项 / 平台模型 | `model_base` | 全局逻辑标识 `model_code` 与展示名，对应客户端请求的模型 id |
| 路由实例 / 可用模型实例 | `model_instance` | 将目录项绑定到某厂商的某条上游，并声明供应商侧模型名与权重等 |
| 模型标识 / 逻辑 id | `model_code` | 对外稳定字符串，**GET `/v1/models`** 与 Chat 路径使用的逻辑模型 id |
| 供应商模型代码 | `provider_model_code` | 上游 API 实际识别的模型名，可与 `model_code` 不同 |
| 上游记录 | `model_upstream.id` | 表主键；实例必须指向一条上游以确定转发目标 |

英文 i18n SHALL 与上表同一语义键对齐（如 `glossary.modelBase`），避免直译丢失区分。

## UI 页面架构与导航（摘要）

- **一级**：模型库 → 默认 **实例列表**（主表 + 筛选 + 主 CTA「配置可用模型」）。
- **二级**：向导（全屏或居中步骤条）与 **高级维护**（原四实体列表，可 Tab 或折叠）。
- **三级**：各实体新建/编辑 **Modal/Drawer**；从内嵌新建打开时叠加子层，完成后回到父表单。

## 交互细节规范（摘要）

- **列表**：实例行操作「编辑」「停用」；列上提供跳转至关联上游/逻辑模型的链接（只读查看或专家模式）。
- **向导**：`Steps` 或纵向时间线；每步底部「上一步 / 下一步」；下一步前 `validate` 当前步字段并检查依赖 API 是否可加载。
- **Select 内嵌新建**：`dropdownRender` 或 `option` 末行「+ 新建…」；打开子 Modal，提交成功后 `invalidateQueries` 并 `setFieldValue`。
- **只读**：与现 `readOnly` 一致，禁用所有写控件与内嵌新建。

## Decisions

| 决策 | 选择 | 理由 | 备选 |
|------|------|------|------|
| 默认 IA | 实例列表优先 | 最接近用户结果「可调用的模型」；与公开列表心智一致 | 仍以厂商优先（否决：仍表驱动） |
| 向导数据流 | 前端分步调用现有 POST 接口，按顺序写入 | 零后端改动；每步成功即可被后续步骤引用 | 单次聚合提交（需新 API，否决） |
| 内嵌新建 UI | Modal 优先，复杂上游用 Drawer | 与现 `EditModal` 模式一致，易复用校验与 `react-hook-form` | 全页路由（否决：打断向导） |
| 状态与缓存 | 继续 `react-query`，每步成功后 `invalidate` 相关 `queryKey`（与现 `invalidateAll` 对齐） | 保证下拉选项新鲜 | 本地临时态（易与服务器不一致） |
| 专家入口 | 二级 Tab 或页面内「高级：按表维护」折叠区 | 不强制老用户改变习惯；降低迁移风险 | 完全移除四表视图（否决：运维排障需要） |
| 术语呈现 | i18n 主文案 + `TermHint` 小组件（Tooltip + glossary 键） | 满足「平民化 + 专业可查」 | 仅改中文文案无释义（不满足需求） |

## Risks / Trade-offs

- **[Risk] 向导步骤与可选跳过** → **Mitigation**：上游依赖厂商 ID、实例依赖三者；向导用前置校验与禁用「下一步」直至必选数据存在；提供「已有数据跳过」勾选仅在对应实体已存在时显示。
- **[Risk] 弹窗嵌套与焦点** → **Mitigation**：内嵌新建使用 Ant Design `Modal` 层级或单一 Drawer，避免三级堆叠；完成后关闭子层并聚焦父表单。
- **[Risk] 文案膨胀** → **Mitigation**：术语表集中维护在 locale 命名空间 `pages.modelLibrary.glossary.*`，避免重复段落。
- **[Risk] 只读角色** → **Mitigation**：与现 `readOnly` 一致隐藏新建/编辑与内嵌新建入口；向导入口对只读隐藏或仅展示说明。
- **Trade-off**：保留专家四表视图会增加维护面积；通过共享表单字段组件与单一路由减少重复。

## Migration Plan

1. 交付新 IA 与向导（默认路由指向新布局）。
2. 保留「高级维护」入口一段时间，监控反馈；无严重问题后可将旧四标签收拢为单一「按表导出/排障」视图或删除。
3. **Rollback**：恢复以 `ModelLibrary.tsx` 旧标签结构为默认（Git revert 或特性开关）；无数据迁移。
