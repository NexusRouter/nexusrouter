## Why

管理端「模型库」沿用四张数据表的独立标签页组织方式，与用户「配置一个可用 AI 模型」的真实任务脱节，导致反复切页、术语晦涩、依赖缺失即卡死。需要在**不改动后端四表结构与 API 契约**的前提下，将信息架构与交互重构为任务驱动与可引导的配置体验，降低运营与实施同学的心智成本。

## What Changes

- 以**模型列表（可路由实例视角）**为主入口，替代「厂商 / 逻辑模型 / 上游 / 实例」四标签平铺；保留专家路径下的分实体精细化管理能力。
- 提供**新手向导式一键配置流程**（按任务顺序串联厂商 → 上游端点 → 逻辑模型 → 实例绑定），与**专家单页/单模块深度编辑**双模式共存。
- **术语平民化**：界面主文案采用业务语言，技术词（如逻辑模型、上游、实例）以副标题、Tooltip、一步内嵌释义呈现；与 `admin-i18n` 中英资源对齐。
- **依赖内嵌创建**：所有关键下拉支持「选择已有 / 快捷新建」；新建在弹窗或侧滑内完成并回写选择，避免为补依赖而切换顶层导航。
- **空态与阻断处理**：缺前置依赖时展示明确下一步（去创建 / 打开向导），禁止静默失败或仅禁用无说明。
- **非目标（明确排除）**：不改 `model_vendor` / `model_base` / `model_upstream` / `model_instance` 表结构；不新增或变更管理端 REST 契约（仅前端编排与组件层）；不与网关路由或 `GET /v1/models` 聚合逻辑耦合变更。

## Capabilities

### New Capabilities

- `model-library-admin-ux`：管理端模型库模块的信息架构、双模式（向导 / 专家）、页面流程、表单与下拉联动、术语与释义、空态与权限下的交互规则；与现有 `model-library` 后端能力正交，仅约束前端呈现与操作路径。

### Modified Capabilities

- （无）后端 `model-library` 数据与 API 行为不变；`dashboard-frontend` 工具链与全局面包屑等基线要求不变，本变更通过新能力规格约束模型库子域，不修改其现有 Requirement 条目。

## Impact

- **代码**：主要影响 `web/dashboard/` 下模型库相关路由、页面、表单与组件（具体路径以实现为准）；可能新增向导步骤组件、内嵌创建弹窗、列表主从布局。
- **API**：沿用现有 `/api/admin/v1` 下模型库 CRUD 与上游同步接口，前端仅调整调用顺序与聚合展示。
- **依赖**：无新增运行时依赖预期；遵循现有 Ant Design、React Query、react-hook-form、zod 与 i18n 体系。
- **风险与兼容**：需回归管理端模型库全链路 CRUD 与只读角色；需验证中英文切换下文案与 Tooltip 完整性。回滚策略为保留功能开关或路由级切换旧版布局（若实现阶段采用特性开关）。
