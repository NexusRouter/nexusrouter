## Context

- **现状**：`GatewayPolicyLayout` 以 Tabs 拆分为 `/gateway/rate-limits`、`/gateway/cors`、`/gateway/ip-access`，标签文案贴近后端模块名（限流、CORS、IP 名单）。各页独立实现保存（如限流 `persist` 写死为 true、CORS 由表单控制）、术语直接暴露维度枚举与英文模式名。
- **约束**：不修改网关对 `gateway.yaml` 及管理 API 的语义；前端仅重组布局、文案、校验与交互；须保持 **zh/en** i18n 与 **Operator 只读** 行为（`isOperatorRole`）。
- **干系人**：自托管管理员、运维；需兼顾偶尔改配置的研发与长期只看不改的值班。

## Goals / Non-Goals

**Goals:**

- 单页（或可深链的锚点分区）内用**三大场景区块**呈现：IP 访问控制、限流规则、跨域配置；用户按意图直达，而非按后端模块名猜测。
- **术语对照**：界面主文案用业务语言，必要时用 Tooltip/次要说明解释与 YAML/API 字段的对应关系。
- **交互模板**：统一「区块内保存」「写回 YAML」开关位置与说明、成功/失败 Message、表单校验时机（失焦或提交）、列表类重复/冲突提示。
- **CORS 分层**：默认仅展示启用、允许来源（标签 + 批量）、预检缓存时间等；方法与请求头等归入「高级配置」折叠面板，默认折叠。
- **风险可见**：对写盘、全局回退限流、名单模式切换等提供简短风险说明；服务端错误原文或字段级错误可映射为用户可读句。

**Non-Goals:**

- 新增或变更管理 API、变更限流/CORS/IP 中间件行为。
- 重做非网关策略类页面（上游、模型库等）。

## Decisions

1. **布局：单页滚动 + 可选深链**  
   - **选择**：以 `/gateway` 或 `/gateway/policy` 为壳组件，内嵌三个 `Card`（或 `Collapse` 仅移动端），每卡对应现有子页面逻辑抽取为**子组件**或保留页面在路由中但通过 `?section=` / hash 同步滚动。  
   - **理由**：满足「一眼看到三大场景」；保留子路由便于书签与分享。  
   - **备选**：仅保留 Tabs 但改名—— rejected：未解决「结构割裂」心智问题。

2. **组件复用**  
   - **选择**：将 `RateLimitRules`、`CorsSettings`、`IpAccess` 的表单与表格主体抽到 `components/gateway-policy/` 或保留页面文件由布局聚合渲染，避免三套不同的 `max-w-*` 与标题层级。  
   - **理由**：统一间距、标题、保存条。  
   - **备选**：iframe 式嵌入—— rejected：可访问性与样式一致性差。

3. **校验**  
   - **选择**：在现有服务端校验基础上增加 **Zod 或 antd Form rules** 做 CIDR、路径前缀格式、正数 RPS/burst、域名/origin 基本形态的前端校验；重复 `priority+path+维度` 等在前端提示，最终以 API 错误为准。  
   - **理由**：降低无效请求；与「不改后端」兼容。  
   - **备选**：仅服务端校验—— rejected：与「误操作风险」目标不符。

4. **写回 `gateway.yaml`（persist）**  
   - **选择**：三区块均提供**一致**的「保存到运行时 + 可选写回配置文件」说明；默认勾选策略与现网行为对齐（若某页当前写死 persist，在设计实施时改为显式开关并默认 true 以保持兼容）。  
   - **理由**：消除「有的页不能关写盘」的困惑。  
   - **备选**：全局单一 persist—— rejected：API 仍为分块 PUT，合并请求需后端配合（超出范围）。

5. **i18n**  
   - **选择**：新增键集中在 `pages.gatewayPolicy.*` 或沿用 `pages.*` 前缀但统一命名；术语表在 `zh.ts`/`en.ts` 同步，不在代码中硬编码中文。  
   - **理由**：符合 `dashboard-frontend` 与 `admin-i18n` 约定。

## 术语对照表（设计层）

| 用户可见（主文案） | 含义 / 后端概念 | 说明文案要点 |
|-------------------|-----------------|--------------|
| 按客户端 IP（连接建立时） | `dimension: ip`，鉴权前 | 强调「尚未识别 API Key，按 IP 计数/匹配」 |
| 按 API 访问身份（识别密钥后） | `dimension: api_key_fp`，鉴权后 | 强调「已识别调用方身份，按密钥维度限流」 |
| 仅允许名单内地址 | `mode: allowlist` | 非名单内请求将被拒绝 |
| 拦截名单内地址 | `mode: denylist` | 命中名单的 IP 将被拒绝 |
| 关闭名单 | `mode: off` | 不做 IP 名单拦截 |
| 允许浏览器来源 | `allow_origins` | 跨域场景下哪些前端域名可调用网关 |
| 允许的 HTTP 方法 | `allow_methods` | 一般仅在高级配置中修改 |
| 写回配置文件 | `persist` + 写 `gateway.yaml` | 重启后仍保留；错误时保留旧配置 |

（实现时在 `locales` 中落地具体字符串；PATCH 等方法名若出现，仅作选项标签并附「用于部分更新类请求」等短说明。）

## UI 页面架构

- **页头**：标题「网关策略」+ 一句场景化副标题（例如：控制谁可以访问、请求频率与浏览器跨域）。  
- **区块顺序**（建议）：① IP 访问控制 → ② 限流规则 → ③ 跨域配置（与安全/流量顺序一致：先门禁、再限流、再浏览器策略）。  
- **每卡结构**：标题 + 可选风险/说明 Alert（仅关键项）→ 表单主体 → 底部操作条：`保存`（主按钮）、`写回 gateway.yaml`（与 `persist` 绑定）、只读时禁用并 Tooltip。  
- **导航**：侧栏仍指向统一入口；原 `/gateway/rate-limits` 等路由 **重定向** 到 `/gateway/policy#rate-limits` 或等价，避免死链。

## 表单与校验规则（前端）

| 区域 | 校验项 | 行为 |
|------|--------|------|
| IP 名单 | CIDR / IP 文本 | 非空行按行校验；非法项标红并阻止提交；与后端「整批失败」策略一致时在 Message 中汇总 |
| 限流 | `priority` 整数、`match_path_prefix` 非空规范、`rps`/`burst` 正数 | 表格内联错误；可选：同前缀+维度下 priority 重复警告 |
| CORS | origin 形态、方法 token、max_age ≥ 0 | 与现有 admin API 错误对齐展示；批量导入去重去空（保持现有逻辑） |

## 风险提示规范

- **位置**：写回 YAML 开关旁一行次要文字；名单模式从 off 切换为 allow/deny 时 **Modal 或 inline Alert** 说明可能影响范围。  
- **文案原则**：说明「影响谁、不生效时如何、失败时是否保留旧配置」三要素中的一到两项，避免长篇技术文档。

## Risks / Trade-offs

- **[Risk] 单页过长** → 使用锚点导航条（页内 sticky）或折叠非当前区块；移动端优先折叠。  
- **[Risk] 三区块同时编辑未保存** → 各卡独立保存，不引入全局 dirty 状态 MVP；后续可加「离开页提示」。  
- **[Risk] 与现习惯路径不一致** → 旧 URL 301/重定向到带 hash 的新 URL。

## Migration Plan

1. 实现新布局与组件抽取，保持 API 不变。  
2. 加路由重定向与 e2e/手测清单（三区块保存、Operator 只读、中英文切换）。  
3. 发布说明：仅前端变更，无需迁移数据。
