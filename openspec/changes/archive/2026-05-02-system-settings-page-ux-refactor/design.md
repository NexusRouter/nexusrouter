## Context

- **现状**：`SystemSettings.tsx` 以 `settings.configKey` + `<code>{s.key}</code>` 展示扁平列表，紧随其后是代理访问日志表单；用户需自行把列表中的 `proxy_access_log_*` 与下方表单对应。`mutability` 仅译为「热更新 / 需重启 / 只读」，未与「如何修改」「是否写盘」联动。GET 接口返回的字段包含 `http_listen_addr`、`upstream_timeout`、`gateway_config_file` 及快照中的日志 enabled/path/level；表单另含 `max_size_mb`、`max_backups`（PUT 支持），但 GET 列表未单独列出这两项——需在设计上用默认值与说明处理，避免暗示「与上方列表一一对应」。
- **约束**：不修改网关 handler 与配置校验逻辑；前端仅重组布局、文案、提示与交互；须保持 **zh/en** i18n、**Operator 只读**（`isOperatorRole`）、现有 API 调用方式。
- **干系人**：自托管运维、偶尔调日志与监听配置的研发；需兼顾「只查看运行参数」与「改日志写盘」两类路径。

## Goals / Non-Goals

**Goals:**

- 三大场景模块：**系统运行状态**（只读）、**代理访问日志**（可编辑）、**高级/技术细节**（可选折叠，含后端键名、环境变量提示等）。
- **术语对照表**在设计与实现中落地：主标签用业务语言，键名降级为辅助信息。
- 保存日志配置后 **刷新** `system-settings` 查询，使只读区与表单一致；成功/失败反馈与现网一致。
- 每项配置具备 **生效方式说明** + **风险或操作提示**（沿用 `hint` 与 mutability 映射，不足处用 i18n 补充短句）。

**Non-Goals:**

- 扩展 GET 返回字段或新增管理 API（若产品后续要求展示 `max_size_mb` 等，另起变更）。
- 在页面内实现「重启进程」或修改宿主机环境变量——仅说明路径与风险。

## Decisions

1. **模块划分与顺序**  
   - **选择**：自上而下：**运行状态** → **代理访问日志** → **高级配置（折叠）**。  
   - **理由**：符合「先看能不能动、再改可热更项、最后查技术细节」的心智。  
   - **备选**：Tabs 分栏—— rejected：模块少，滚动 + 折叠更轻量。

2. **运行状态区展示形态**  
   - **选择**：使用 **Card + 描述列表（或行式）**，每行：**业务标题**、**当前值**、**生效方式标签**、**说明/风险**（`hint` + 固定短语）；不将 `key` 作为主标题。  
   - **理由**：消除「变量_dump」观感；与网关策略页 Card 模式一致。  
   - **备选**：保留 code 主标题—— rejected：与「术语平民化」冲突。

3. **键名与 API 字段的暴露**  
   - **选择**：在「高级配置」折叠面板或每行次要位置展示 `key` 与（若有）环境变量名，可复制；默认折叠。  
   - **理由**：排障仍需对齐 YAML/文档，但不抢占主阅读路径。

4. **日志表单**  
   - **选择**：保留现有 Ant Design Form 字段与 `PUT` 结构；在区块标题下增加一句**与运行状态联动**的说明（例如保存后上方「当前是否启用/路径」更新）。  
   - **理由**：零后端改动；达成「修改后与状态模块实时联动」通过 React Query 刷新实现。

5. **生效方式与风险文案**  
   - **选择**：`hot_reload` → 主文案强调「保存后可热生效 / 可选写回 gateway.yaml」；`restart_required` → 明确「须改环境变量并重启进程，本页不可在线修改」；`read_only` → 「仅展示，修改方式见说明」。风险：写盘失败、路径无效等继续展示 API 返回信息。  
   - **理由**：与后端 `mutability`/`hint` 一致，减少臆造行为。

6. **i18n**  
   - **选择**：新增键归组在 `settings.*`（或 `pages.settings.*` 子树），业务标题与 mutability 说明键一一对应中英文；不在 TSX 中硬编码中文。

## 术语对照表（设计层）

| 用户可见（主文案） | 后端 `key` / 概念 | mutability | 说明要点 |
|-------------------|-------------------|------------|----------|
| HTTP 监听地址 | `http_listen_addr` | restart_required | 修改 `NEXUSROUTER_HTTP_LISTEN_ADDR`，重启进程 |
| 上游请求超时 | `upstream_timeout` | restart_required | 修改 `NEXUSROUTER_UPSTREAM_TIMEOUT`，重启进程 |
| 网关配置文件路径 | `gateway_config_file` | read_only | 一般由环境指定，修改须改环境变量并重启 |
| 启用代理访问日志 | `proxy_access_log_enabled` | hot_reload | 与下方表单同一语义；保存后热生效 |
| 日志文件路径 | `proxy_access_log_path` | hot_reload | 路径须对进程可写 |
| 日志级别 | `proxy_access_log_level` | hot_reload | 与表单一致 |
| 单文件上限（MB） | （PUT: `max_size_mb`，GET 列表未单列） | hot_reload | 在表单区编辑；与列表不对齐时在区块内简短说明 |
| 保留文件个数 | （PUT: `max_backups`，GET 列表未单列） | hot_reload | 同上 |

（实现时以 `locales` 为准；若 API 日后扩展 GET 字段，再移除「未在列表展示」的说明。）

## UI 页面架构

- **页头**：标题「系统设置」+ 一句场景化副标题（当前进程可见配置与可热更新项）。  
- **区块一 — 系统运行状态**：`Card`，内为只读列表；无编辑控件；Operator 与 Admin 均可看。  
- **区块二 — 代理访问日志**：`Card`，内为现有表单；底部主按钮「保存」+「写回 gateway.yaml」开关；Operator 禁用整表。  
- **区块三 — 高级配置（可选）**：`Collapse` 默认折叠；展示键名对照、环境变量名、与 `gateway.yaml` 片段关系等短说明。  
- **视觉**：最大宽度与侧栏导航对齐现有管理页（如 `max-w-*` 与 `space-y`）；暗色模式与边框样式与同目录其他页一致。

## 表单设计

- **字段顺序**：启用开关 → 路径 → 级别 → 单文件上限 → 保留个数 → 写回 YAML（`persist`）。  
- **校验**：保持服务端校验为主；前端可对路径非空（启用时）、数值下限做即时提示（与现网一致即可）。  
- **加载态**：查询 loading 时骨架或 Spin；提交时按钮 loading。

## 状态提示与风险提示规范

- **生效方式**：使用 Tag 或次要文本三色以内区分「热更新 / 需重启 / 只读」，**同一词汇**在列表区与高级说明中一致。  
- **风险**：写回 `gateway.yaml` 在开关旁一行次要文字；路径类提示磁盘权限与进程用户；不夸大未实现的后果。  
- **操作员**：在页顶或表单上方保留「仅可查看」警告（现有 `operatorReadOnly`）。

## Risks / Trade-offs

- **[Risk] GET 未返回 max_size_mb / max_backups** → 在日志卡片内用一行说明「轮转参数在下方表单配置」，避免用户在上表找对应行。  
- **[Risk] 折叠高级信息后排障不便** → 提供「展开全部技术名称」或复制键名；保持默认折叠减少噪音。  
- **[Risk] 文案过长** → 主句一行，详情 Tooltip 或 Collapse 内短段落。

## Migration Plan

1. 实现布局与 i18n，不改 API。  
2. 手测：Admin 保存、Operator 只读、中英文、保存后列表刷新。  
3. 发布说明：仅前端变更。
