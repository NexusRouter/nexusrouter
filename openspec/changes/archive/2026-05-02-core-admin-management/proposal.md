## Why

运维与管理员需要在统一的管理面板中完成身份认证、观测网关运行状况、维护上游代理与 API Key，并在同一界面调试网关 HTTP 接口。当前能力分散在环境变量、文件热加载与独立 Swagger 地址，缺少面向管理员的闭环体验，运维成本高且不利于安全审计。

## What Changes

- 增加**管理端登录**：管理员账号密码登录，签发并持有**权限令牌**；未认证访问受保护管理路由时**重定向至登录页**；支持**记住密码**（安全存储约定在设计中明确）；支持**忘记密码**流程（邮件或管理员重置等可实施方案在设计中选定）。
- 增加**管理仪表盘**：展示网关**在线状态**、**当前请求量**、**成功率**、**平均耗时**；提供**今日 / 昨日请求对比**与**错误类型分布/统计**等核心指标。
- 增加**代理（上游）配置管理**：在面板中**可视化**维护上游列表；支持**新增、编辑、删除**、**设置默认上游**；变更**实时生效**；可查看**当前生效的上游地址**（与运行时一致）。
- 增加 **API Key 管理界面**：列表展示全部 Key（**脱敏**、状态、有效期、创建时间）；支持**新增、禁用、删除**；支持**批量**禁用/删除等操作（与现有密钥文件或存储模型对齐）。
- 在管理面板内**嵌入 Swagger UI**（或等价组件），可直接调试网关 OpenAPI 文档中的接口，**无需**单独打开独立 Swagger 地址。

## Capabilities

### New Capabilities

- `admin-auth`: 管理端身份认证与会话/令牌、未登录重定向、记住密码与忘记密码流程的契约。
- `admin-dashboard-metrics`: 管理仪表盘展示的网关运行状态与核心指标（含今日/昨日对比、错误类型统计）的数据与展示要求。
- `admin-upstream-management`: 上游代理的可视化配置、默认上游、实时生效与当前生效地址可观测性的端到端要求。
- `admin-api-key-console`: 管理端对 API Key 的列表（脱敏）、生命周期与批量操作的 UI 与配套后端契约（与网关鉴权数据源一致）。
- `admin-swagger-embed`: 在管理面板内嵌网关 API 文档/调试能力（Swagger UI 或等价）的集成与访问控制要求。

### Modified Capabilities

- `dashboard-frontend`: 扩展为包含登录页、仪表盘、上游配置、API Key 管理、内嵌文档等路由与布局；受保护页需认证。
- `gateway-backend`: 扩展 HTTP 能力：管理端认证、指标聚合或查询接口、上游与 API Key 的受控管理接口（在保持现有 OpenAI 兼容与错误约定前提下增量）。
- `api-key-management`: 若管理操作从「仅文件 + 热加载」扩展为可编程 CRUD/批量，则补充**与运行时一致**的密钥元数据与重载/生效规则。

## Impact

- **后端**（`services/gateway/`）：新增或扩展管理 API、可能的指标采集/存储、认证与授权中间件；与现有 `AdminReloadToken`、上游运行时、`KeyStore` 的集成方式需在实现中统一，避免双源真理。
- **前端**（`web/dashboard/`）：新页面与导航、认证状态、图表与表格、内嵌 Swagger UI（iframe 或 npm 包）。
- **配置与运维**：可能新增密钥、会话、邮件（若忘记密码走邮件）等环境变量；部署文档与 `README` 需同步。
- **安全**：管理接口 MUST 限权、HTTPS 部署建议、令牌与 Key 脱敏、审计日志（建议在设计中约定）。
