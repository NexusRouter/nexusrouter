## Context

NexusRouter 网关与管理仪表盘已具备 Go + Gin 后端与 React + Vite 前端基线。本变更在**系统全局**（非租户）维度引入「首次部署未完成配置」状态，要求与现有错误 JSON 约定、请求 ID 中间件及管理端认证体系**可组合**：未初始化阶段大量接口需被拦截，但初始化与状态查询需**匿名可达**；初始化完成后向导入口必须关闭；运维重置必须绑定**超级管理员**身份。

## Goals / Non-Goals

**Goals:**

- 在数据库中持久化**布尔语义**的已初始化标志及辅助字段（如初始化进行中标记、版本号），进程重启与水平扩容下行为一致。
- 通过**单一数据库事务**创建超管、写入基础配置、翻转已初始化标志；任一步失败则**不提交**事务。
- 对「完成初始化」接口实现**至多一次成功**语义；成功后接口返回明确「已锁定」错误且**不改变**数据。
- 未初始化时：除**初始化向导静态资源**、**状态 GET**、**完成初始化 POST**（及健康检查等在设计中列明的豁免项）外，其余 HTTP 与前端路由一律拒绝或重定向到向导。
- 敏感字段（至少超管密码）使用行业标准的**单向密码散列**（如 Argon2id 或 bcrypt）存储；若存在需可逆解密的配置密钥，使用**应用级对称加密**（密钥来自环境变量或 KMS），**禁止**明文落库。
- 并发：同一时刻仅一个初始化事务可成功提交；其他并发提交返回**冲突/进行中**类稳定 `code`。
- 提供**超级管理员**可调用的「重置为未初始化」接口；重置后清除或失效由实现定义的敏感派生状态（如强制下线会话在设计中细化）。

**Non-Goals:**

- 多租户独立初始化、分环境配置模板导入、向导内嵌第三方 IdP。
- 通过修改本地 yaml/json 文件完成首次初始化（本向导为默认路径，文件方式可继续存在但不替代 DB 权威状态）。
- 未初始化期间开放只读业务 API（除明确豁免外一律拦截）。

## Decisions

1. **权威状态存储**  
   - **决策**：使用关系库（与现有 GORM/迁移一致）**单行**系统表（如 `system_bootstrap`：`initialized`、`init_lock_token` 或 `init_started_at`、行版本 `lock_version`）。  
   - **理由**：与「全局、非用户绑定」一致，便于 `SELECT ... FOR UPDATE` 实现互斥。  
   - **备选**：Redis 分布式锁 — 增加运维依赖且重启需与 DB 对齐，弃用为主锁，仅可作为可选加速。

2. **中间件顺序**  
   - **决策**：在 **RequestID** 之后、**认证与业务路由**之前注册 **BootstrapGate**：读取 DB 缓存或短 TTL 缓存的初始化标志；未初始化时比对路径白名单。  
   - **理由**：统一入口、对业务 handler 无侵入；白名单与代码审查可集中管理。  
   - **备选**：在每个 handler 开头判断 — 易遗漏，否决。

3. **「初始化中」语义**  
   - **决策**：在提交初始化前，由服务端在**同一事务**内先写入 `init_in_progress`（或等价）+ 超时时间戳，提交成功则置 `initialized=true` 并清除进行中；失败回滚。客户端轮询状态接口返回 `initializing` / `pending` 枚举。  
   - **理由**：满足「仅第一个请求可完成」的可测试语义；超时由后台任务或下次请求惰性清理（具体 TTL 在实现中选 60–300s）。  
   - **备选**：纯内存锁 — 多副本不一致，否决。

4. **一次性成功**  
   - **决策**：`initialized` 一旦为 true，`POST .../complete` MUST 返回 **409**（或 **423**）及稳定 `code: bootstrap_already_completed`，且**禁止**再次修改超管密码或初始化 payload。  
   - **理由**：满足「永久锁定」产品要求。

5. **重置接口鉴权**  
   - **决策**：`POST .../reset` MUST 要求**已认证**且角色为**超级管理员**（与现有 RBAC 模型对齐；若尚无角色表则本变更引入最小 `is_super_admin` 或等价声明）。  
   - **理由**：满足「仅超管可调用」；与公开初始化端点分离。

6. **前端路由**  
   - **决策**：React Router **loader** 或布局级 **effect** 在应用根拉取 `/bootstrap/status`；未初始化时 `Navigate` 至 `/setup`；已初始化访问 `/setup` 时重定向至 `/login`。  
   - **理由**：与后端门闸一致、避免闪屏可通过骨架与 SWR 缓存优化。

7. **密码存储**  
   - **决策**：超管密码 MUST 使用 **Argon2id**（若依赖引入成本受限则 **bcrypt cost ≥ 10**）仅存散列。  
   - **理由**：符合「加密存储」工程解读与合规常见要求。

## Risks / Trade-offs

- **[Risk] DB 不可用导致无法拉取状态** → 门闸默认**拒绝非白名单**（安全优先），白名单保留 `/health`（若存在）与静态资源路径；首页返回 503 与统一 JSON（若走 API）。  
- **[Risk] 重置误操作导致锁死** → 重置 MUST 二次确认由前端承担；后端记录审计日志（建议 ADDED 到实现任务）。  
- **[Trade-off] 缓存初始化标志** → 降低 DB 压力但多实例短暂不一致；采用**短 TTL（如 5s）+ 写入后主动失效**或仅进程内缓存并接受极短窗口。

## Migration Plan

1. 新增迁移：创建 `system_bootstrap`（或命名一致）表及默认行 `initialized=false`。  
2. 部署新版本：旧数据无表时迁移自动补齐；首次请求走向导。  
3. 回滚版本：若回滚到无门闸旧版，旧版**不读**该表则行为退化（可能跳过向导）— 文档说明「回滚需同时恢复备份或手动删表」；生产建议**不回滚**仅向前修复。

## Open Questions

- 管理 API 前缀（`/admin` vs `/api/admin`）与初始化路径的最终命名是否与现有 OpenAPI 文档统一，需在实现前对照 `core-admin-management` 已落地路由。  
- 「系统基础配置」首版字段清单（站点名、对外 URL、邮件 SMTP 等）需产品确认；本提案允许**最小子集**（仅超管账号 + 站点显示名）首发。
