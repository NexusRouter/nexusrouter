## Why

全新部署的 SaaS 管理端在首次访问前没有引导流程，管理员必须依赖文档修改配置或直连数据库才能完成超管与基础设置，部署体验差且易出错。需要在**数据库持久化**的全局「未初始化 / 已初始化」状态下，提供**一次性**可视化向导，并在未初始化期间**统一拦截**非向导流量，同时保留超级管理员在运维场景下的**受控重置**能力。

## What Changes

- 引入**系统级首次启动（First Boot）**流程：数据库记录全局初始化状态；未初始化时仅允许访问**初始化配置页**与**初始化状态查询**相关能力，其余前端路由与后端 HTTP API（除公开初始化提交与状态查询外）**一律拦截**并引导至初始化页。
- 初始化向导：收集**超级管理员账号**与**系统基础配置**（具体字段在设计中枚举）；提交在**单事务**内完成，失败**整单回滚**；成功后标记**已初始化**并**永久锁定**初始化提交接口（成功调用仅允许一次）。
- **并发与防重**：多人同时访问时，仅首个可完成有效初始化；其余用户看到**初始化进行中**或等价提示（基于行锁 / 乐观版本 / 分布式锁等策略在设计中选定）。
- **安全**：初始化提交与状态查询在未初始化阶段可**匿名**访问；**重置为未初始化**仅**超级管理员**可调；密码等敏感字段**加密存储**（算法与密钥管理在设计中明确）。
- **已初始化后**：禁止再访问初始化向导页（自动跳转**登录页**）；初始化成功路径对用户透明，不侵入现有业务逻辑，仅通过全局状态与中间件/路由守卫控制。

## Capabilities

### New Capabilities

- `saas-first-boot-initialization`: 全局初始化状态模型、一次性初始化事务、公开初始化与状态 API、超管专属重置 API、并发语义、敏感数据加密与错误/锁定语义的端到端契约。

### Modified Capabilities

- `gateway-backend`: 增加基于全局初始化状态的请求拦截顺序与公开端点白名单；扩展或新增初始化与重置相关 HTTP 行为，且与现有 JSON 错误约定兼容。
- `dashboard-frontend`: 增加初始化向导路由与布局；未初始化时全局重定向/路由守卫；已初始化时禁止访问向导并跳转登录。

## Impact

- **后端**（`services/gateway/`）：新表或键值存储模型、迁移、中间件/路由分组、初始化与重置处理器、与现有管理员认证/超管角色的衔接。
- **前端**（`web/dashboard/`）：新页面、路由表与导航守卫、与初始化状态 API 的集成。
- **运维与数据**：首次部署无需手工改库；重置后需重新完成向导，文档需说明风险与权限。
