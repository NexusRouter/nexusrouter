## ADDED Requirements

### Requirement: 网关运行状态展示

管理仪表盘 MUST 展示网关**在线/离线**状态（以可探测的健康或心跳为准）、**当前请求量**（实现定义的速率或窗口内计数）、**成功率**与**平均耗时**（覆盖至少 **`POST /v1/chat/completions`** 或文档声明的统计范围）。

#### Scenario: 服务健康时显示在线

- **WHEN** 网关进程正常响应健康检查且指标模块可用
- **THEN** 仪表盘将运行状态呈现为在线，并展示非空的请求量/成功率/耗时指标

#### Scenario: 服务不可达时显示离线或错误

- **WHEN** 前端无法连接网关或健康检查失败
- **THEN** 仪表盘 MUST 呈现离线或错误状态，且 MUST NOT 伪造成功指标

### Requirement: 今日与昨日请求对比

仪表盘 MUST 提供**今日**与**昨日**请求量（或等价业务量）的对比展示；「日」边界 MUST 与 `design.md` 声明的时区/UTC 规则一致并在实现中固定。

#### Scenario: 跨日切换后归属正确

- **WHEN** 当前时间跨越配置的日界
- **THEN** 「今日」计数 MUST 重置或滚动到新日，「昨日」展示上一完整日数据

### Requirement: 错误类型统计

仪表盘 MUST 展示**错误类型**分布或排行，来源 MUST 为网关统一错误 **`code`**（或等价枚举），聚合维度在实现中定义（至少包含鉴权失败、上游错误等可区分类型）。

#### Scenario: 无错误时有明确空态

- **WHEN** 统计窗口内无任何错误
- **THEN** 界面 MUST 展示零或空态，而非崩溃或 NaN
