# admin-console-global-ux Specification

## Purpose

约束管理控制台（`web/dashboard`）的全局体验基线：侧栏信息架构、导航高亮、危险操作确认、空态与加载错误反馈、术语层级、跨页引导与只读权限说明，且不要求变更既有管理 API。

## Requirements

### Requirement: 侧栏信息架构与域分组

`web/dashboard` 已登录管理布局的侧栏导航 MUST 将现有条目组织为**至少两个层级**：**域（分组标题）**与**菜单项**，且 MUST NOT 改变各菜单项既有 `path` 与路由注册方式。分组 MUST 覆盖当前全部一级业务入口：仪表盘、上游、模型库、API Key、访问日志、网关策略、系统设置。移动端抽屉导航 MUST 与桌面侧栏使用同一套分组与顺序。

#### Scenario: 分组可见且顺序一致

- **WHEN** 管理员在桌面宽度打开控制台
- **THEN** 侧栏展示域标题与各入口，且顺序与规格或产品映射表一致

#### Scenario: 移动端同构

- **WHEN** 用户在窄屏打开抽屉菜单
- **THEN** 分组与菜单项与桌面侧栏一致，无缺失入口

### Requirement: 导航高亮与路径匹配

当前路径 MUST 正确映射到唯一高亮菜单项；对 `/gateway` 下子路径 MUST 高亮「网关策略」项；对 `/model-library` 下可能存在的子路径 MUST 高亮「模型库」项。默认落地页（如 `/` → `/dashboard`）行为 MUST 与变更前一致。

#### Scenario: 网关策略深路径

- **WHEN** 用户访问 `/gateway/policy` 或带 hash 的等价 URL
- **THEN** 「网关策略」菜单项处于选中态

### Requirement: 危险操作分级与统一确认

对**删除或不可逆**类操作（包括但不限于删除 API Key、上游、模型库厂商/模型/上游/实例、限流/CORS/IP 规则条目等），界面 MUST 使用**模态确认**（或等价的专注层对话框），且 MUST 在文案中说明**操作对象**（名称或主键）与**不可恢复性**。MUST NOT 仅依赖行内 `danger` 按钮无确认即调用删除 API。统一确认组件 MAY 抽取为共享模块，但行为必须符合本要求。

#### Scenario: 删除需确认

- **WHEN** 用户触发删除某条可命名资源
- **THEN** 在 API 调用前出现确认对话框，且展示该资源的识别信息

### Requirement: 空态、加载与错误基线

各管理页 MUST 在数据为空、请求进行中、请求失败时提供与用户任务相关的反馈：**空态**须包含简短引导（下一步可去哪里或需先配置什么）；**加载**须避免布局跳动（骨架屏或 Spin）；**错误**须可读且可恢复（重试或返回），且 MUST NOT 静默失败。具体文案 MUST 走 i18n。

#### Scenario: 列表空数据

- **WHEN** 某列表查询成功且记录数为 0
- **THEN** 用户看到空态说明而非空白表格

#### Scenario: 请求失败

- **WHEN** 列表或详情请求失败
- **THEN** 用户看到错误提示并可重试或知晓失败原因（含网络与管理 API 错误消息映射）

### Requirement: 术语与主副文案层级

控制台用户主文案 MUST 使用业务向术语；**后端配置键名**、**snake_case 标识符**、**HTTP 头名称** MUST NOT 作为标题或唯一主标签，MAY 作为次要信息、代码块或 Tooltip。`admin-i18n` 中 MUST 存在可复用的术语表或等价键前缀供侧栏、页标题与跨页提示引用。

#### Scenario: 键名不充当标题

- **WHEN** 用户阅读任意管理页主标题或表单主标签
- **THEN** 首要语言为用户面向术语而非未解释的裸键名

### Requirement: 跨页引导与排障链路

在**无上游/无密钥/无模型实例**等阻塞下一任务的状态下，相关页 MUST 提供指向**推荐下一步**的链接或按钮（使用现有路由），且 MUST NOT 虚构不存在的 API。访问日志与网关策略页 SHOULD 在适用场景提供互链（例如从策略页提示查看日志），链目标 MUST 为已实现路由。

#### Scenario: 空态可跳转

- **WHEN** 某页因缺少前置配置而无法继续
- **THEN** 空态或提示中包含到达配置页的入口

### Requirement: 权限禁用可解释性

当当前用户为 `operator` 或字段只读导致控件禁用时，界面 MUST 通过 Tooltip、`Alert` 或辅助文案说明**原因**（与 `admin-rbac` 一致），MUST NOT 仅禁用无提示致使用户误以为故障。

#### Scenario: 操作员只读

- **WHEN** 操作员打开含写操作的页面
- **THEN** 写操作不可用且可见只读或权限相关说明

### Requirement: 后端兼容与非回归

本能力规范所要求的行为 MUST 仅通过前端交互与文案实现；MUST NOT 要求新增或变更管理 API 的路径、方法或 JSON schema。MUST 保持 Bootstrap、登录、告警条、系统设置与网关策略等现有功能在集成测试或手工回归中可验证。

#### Scenario: API 形状不变

- **WHEN** 开发者抓取重构前后的网络请求（同一用户操作路径）
- **THEN** 请求 URL 与方法集合与重构前一致（除用户主动修改的数据外）
